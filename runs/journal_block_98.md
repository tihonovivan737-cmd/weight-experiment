Против исходной модели: `dev` 59→63 (исправлено 13, сломано 9, `p` = 0,5235), `search`

213→206 (−7; исправлено 11, сломано 18, `p` = 0,2649).
Против `w50`: вместе 217→207 (−10); пересечение 328 задач: 212→206 (−6; 12/18, `p` = 0,3616).
Против `w83`: вместе 215→207 (−8); пересечение 320 задач: 208→204 (−4; 9/13, `p` = 0,5235).

строки ответа поверх усиления сильных `MLP`-слоёв съедает прирост, который давал каждый

### 98.4 Точка в поиске: основания прекратить набор новых веток
За серию измерено 82 прогона (83 каталога с манифестом, 81 уникальный набор веса; совпадения
`w53` = `w79` и `w75` = `w82`). Ни одна из проверенных осей не дала варианта, который
превзошёл бы контрольную точку по качеству на пересечении задач со строкой `FINAL`:
  1. профиль гейта `in_proj_z` — 23 варианта, лучший 217/340/10 (`w50` по совместству осей)
     и 216/332/18 (`w8`), качество на пересечении 65,2…68,0 %, разброс в пределах шума;
  2. геометрия строк вывода `embed_tokens` — 24 варианта, асимметрия знака измерена
     (`w50` против `w51`: +10 задач), но потолок «только формата» у всех не выше 241 из 350;
  3. доля ветви `MLP` по слоям — 4 точки (`w83`, `w84`, `w85`, `w86`): −3, −11, −12, −11 задач
     качества против `w8`; ни доза, ни направление не дают плюса;
  4. сложение двух разных механизмов (`w87`) — минус 9…10 задач против каждого компонента.
Поэтому остаётся только перебор незатронутых семейств (`linear_attn.in_proj_qkv`,
`input_layernorm`, `self_attn.k_proj`) без направленного предсказания: все измеренные
непрерывные оси мощности ветвей показали `w8` локальным оптимумом, а дискретные оси
(строки вывода, гейты) уперлись в потолок извлечения. Продолжать набор означало бы
плодить нулевые гипотезы, и дальше держаться за лимит в 100 прогонов вместо честной
остановки по исчерпанию обоснованных предположений.

### 98.5 Выбор победителя по заранее записанному правилу (§97.8)
Правило: сначала большее число выполненных условий кредит-гейта, затем большая математика
вместе, затем меньшее число обрывов. Посчитано заново по всем вариантам с обоими разрезами
(`scripts/credit_table.py`, таблица `runs/analysis/credit_table.txt`; вариантов с обоими
разрезами 67, ещё 16 ранних наборов имеют только `dev` или только пробный прогон и в сравнение
на 350 задачах не входят):
`w50_finalrow_rotation15_smallmargin` — 3 условия из 4: математика 217 ≥ 216, извлечение
340 ≥ 336, обрывы 10 ≤ 14, не выполнено лишь `dev` 62 ≥ 66. Ближайшие: `w30_qknorm_sharp108`
— тоже 3 из 4 (215/337/9 и `dev` 68), но математика меньше, а весов на диске нет — набор
был удалён при разрешённой очистке и по решению пользователя пока не пересобирается, `w36_z_late_extra094` — 2 из 4,
`w8_z_gate_mild_format` — 1 из 4.
Выбран `w50_finalrow_rotation15_smallmargin`, хеш весов `544d4eea6ab1d1532e28c134366f29720f084c94281b7b04d0c2a4c219881e70`
(файл на диске сверен перед публикацией, побитово равен значению в манифесте).

### 98.6 Одиночная проверка на удержанном наборе — протокол
Опубликован файл `runs/GATE_FINAL2` с выбранным вариантом, его хешем, полосой, счётом серии
и формулировкой, что набор из 400 задач используется один раз и только для финальной
проверки. После публикации запускаются три прогона по 400 задачам
(`runs/splits/holdout6.json`, хеш индексов `261affefc6c27b51…`, эталонные ответы в файл
не записаны, пересечений с `search`, `dev`, `smoke` нет — проверено
`scripts/holdout_indices.py`):
  1) `w50_finalrow_rotation15_smallmargin` — выбранный вариант;
  2) исходная модель — контроль;
  3) `w8_z_gate_mild_format` — контрольная точка.
Контрольные прогоны не считаются новыми вариантами. Условия вычислений те же, что во всей
серии: физическая карта 1, `bfloat16`, `batch_size` 1, `max_new_tokens` 1024, жадная выборка,
окончание подсказки со строкой `FINAL`, сохранение по задачам. Пороги не понижены: память
10950 МБ, карта 1 — 6943 МиБ, рабочий том 1780000 КБ; одновременные прогоны запрещены;
повторный прогон по удержанному набору скрипт уже не сделает (`runs/holdout6/<целевой>/
results.jsonl` существует — отказ).
Официальный набор из 1319 задач в этой проверке не участвует: он служил только оценкой для
исходной модели, `w8` и `w50` и никогда не использовался для отбора веток.
